Extracting Assets/UGS into a UPM package

Status of crawfis/EventDrivenUGS — three packages, compiling clean, audited and published.

The two blockers, and why they were one

The extraction as originally scoped could not ship. Two independent findings turned out to have a single root cause.

1 — Licence. The 81 vendored files under ThirdParty/Blocks/ are Unity Asset Store Extension Asset content. The Asset Store EULA FAQ addresses this exact shape directly:

“A product is not ‘incorporated’ into the Licensed Product if it is designed to allow your end users to extract or download assets separately from the Licensed Product.”

A UPM package is precisely a thing consumers download and whose assets get extracted into their project. Runtime/ versus Samples~/ makes no difference, and neither does a private repo. The tree’s own THIRD-PARTY-NOTICES.md had flagged that this check would come due.

2 — GeneratedBindings. Found independently by 7 of 8 survey dimensions. CrawfisSoftware.UGS.asmdef referenced Unity.Services.CloudCode.GeneratedBindings, whose asmdef lives at Assets/CloudCode/GeneratedModuleBindings/ — in the consumer’s Assets/. A package assembly cannot reference that, so the package would not compile at all. Vendoring a copy fails too: the bindings folder and its asmdef name are hard-coded and regenerated on every “Generate All Modules Bindings”, producing a duplicate-assembly collision.

One cause. Of the 11 files needing GeneratedBindings, 6 were the dead scripts already slated for deletion and 5 were inside the Blocks tree. After the deletions, Blocks was its sole consumer — so removing Blocks from the package dissolved both blockers at once.

Defects fixed along the way

These were live bugs in the existing code, found by reading it closely enough to replace it.

WhereDefect
DebugEventFileLogger Unguarded [RuntimeInitializeOnLoadMethod] opened debug_event_log.txt with append:false next to the executable on every run of every project referencing the package — truncating a file at the project root each Play, and throwing UnauthorizedAccessException from Awake in a Program Files install. Now editor/dev-build only, persistentDataPath in players, open failures warned rather than propagated.
Both achievement hooks Yielded a Task from inside a coroutine. A coroutine yielding a non-YieldInstruction just resumes next frame, so every unlock was fire-and-forget with unobserved exceptions.
DistanceBasedAchievements Looked the achievement up and dereferenced the result; Find returns null until the catalogue is fetched, so the first unlock threw before it was attempted. Also subscribed an anonymous lambda with no unsubscribe — the repo’s one hard rule.
LeaderboardPlayerController data as float? then .Value. A null or non-float payload threw from inside the handler, killing the submission without publishing a failure.
Achievement icons A shared static list, last-writer-wins: whichever of the panel and the toast initialised second blanked the other’s icons. The notification prefab carried a hand-written guard for it. The icon library now merges by name; the guard is gone.
PlayerSignInController Registered a signed-in callback duplicating a subscription it already had — and which, unlike the subscription, could never be unregistered.

Contracts that fail silently

Three names are load-bearing beyond C#. Each breaks at runtime with no compile error, so each carries a comment at its declaration.

  • "hidden" — the USS class PlayerSignInController declares as its own literal. Renaming it in the stylesheet alone hides nothing.
  • Icon filenames — thumbnail, _blue, _green, _red, _black. Matched against Texture2D.name from definitions that live server-side in Remote Config, so a renamed asset breaks a deployed game.
  • <CrawfisSoftware.UGS.Authentication.PlayerSignIn/> — a UXML tag resolved by string at import. Rename the class or namespace and the modal renders empty.

The audit

After the code was complete, the whole extraction was surveyed again across eleven dimensions against the real SDK sources on disk. Every finding was then attacked by three independent skeptics with different lenses - one checking it against the SDK, one hunting for the guard the finder missed, one attacking its impact - and kept only on a majority. 110 findings, 45 confirmed, 45 refuted, plus 11 more from a completeness pass asking what the survey had missed.

All of them are applied. The four that mattered most:

Cloud Save achievements were reading and writing the wrong access class. The replacement used Default; the code it replaced used Public. Those are separate server-side stores on separate endpoints, so the backend could not have seen a single record an existing player already had - every achievement would have silently reappeared locked. The read-modify-write also carried no write lock, so two unlocks landing together lost one.

A failed score submission wedged the game. The failure path never cleared the in-flight flag, so the close coroutine parked on its WaitUntil forever, LeaderboardClosing was never published, and the player never got back to the menu.

The achievements UI went deaf after one panel reload, and the catalogue was never loaded at all. Both elements subscribed in their constructors and unsubscribed on detach with nothing to re-subscribe - and a PanelRenderer rebuilds its tree on every reload. Meanwhile the catalogue's only loader ran at scene Awake, long before sign-in, so every unlock reached the backend and announced nothing.

The access token was written to Player.log on every sign-in. It is a bearer credential and the logger carries no build guard, so in a release build anyone with the log file could act as that player until it expired.

What remains

closed  Compile verification. All three packages now build under Unity 6000.5.7f1 with zero errors and zero warnings, for the editor target and for a player build — the latter matters because an editor-only compile does not define away UNITY_EDITOR and does not run Unity's serialization analyser.

The method: a throwaway host project holding nothing but ProjectSettings/ProjectVersion.txt and a Packages/manifest.json that pulls EventsPublisher by git URL and the three packages by absolute file: path, then Unity.exe -batchmode -nographics -quit -projectPath <host> -logFile <log> -disable-assembly-updater, plus -executeMethod on an editor script calling BuildPipeline.BuildPlayer. Local file: packages are mutable, so Unity writes any missing .meta straight back into the repo.

What it found, in four defects: a using missing for the namespace that declares RequestFailedException; a Cloud Save delete bound to the deprecated overload, because the replacement has no default for its options parameter; a public VisualElement field Unity tried and failed to serialize; and GameManagerUGS, a Match3-sample leftover referenced by nothing in either repo, whose only signal is already published with an identical payload by a class that is scene-wired.

closed  The leaderboard display. Built: LeaderboardPanel → LeaderboardView → LeaderboardList → LeaderboardRow. Two departures from the design spec, both because the spec predates the theme that actually shipped: the tabs are two Toggles rather than a TabView, because UgsComponents.uss styles .ugs-tab-button .unity-toggle__checkmark and a TabView would have quietly lost every tab rule in the sheet; and the panel-level classes the spec named had no rules at all, so they were added to the stylesheet and to UgsUiTheme together.

Three refresh paths overlap — Start, LeaderboardOpened and ScoreUpdated — so each read carries a generation number and a superseded completion is discarded rather than allowed to overwrite a newer one.

closed  The .ach importer. Dropped and replaced, as the survey recommended: AchievementDefinitionCatalog (a ScriptableObject you create in your own project), AchievementDefinitionExporter, and a code-only inspector, in a new editor-only assembly.

It exports .rc, not .ach. That distinction is load-bearing: .ach was never a Unity format — only the vendored ScriptedImporter made it a Deployment item — so with that importer gone an exported .ach would be a file the Deployment window cannot see. The envelope is identical, so Import from JSON still reads your existing Achievements.ach unchanged.

Both measured defects in the code it replaces are fixed by construction: paths resolve through FileUtil.GetPhysicalPath, which handles Packages/ as well as Assets/; and a failed write returns false instead of reporting success after catching the exception. Verified by running it, not only compiling it — 28 checks covering the envelope shape, escaping, a full round trip, the empty case, id validation and path normalisation.

AchievementsAccessControl.ac still should not travel — it denies player writes to Cloud Save, which is exactly incompatible with the default backend.

closed  Scenes and prefabs. Built, and driven through Unity's own editor API in batch mode rather than by editing YAML - so Unity wrote the serialization and Unity checked the result. Samples~/UGS-Scenes holds eight scenes and three prefabs, and every reference in them resolves against the three packages alone: verified by opening all eleven in a project containing nothing else and requiring zero unresolved references.

Unity's own count of what was broken was 30 references, not the 13 a by-hand GUID count gives, because a prefab instance in a scene carries its own overrides and each dangling override is a separate site. Fixing the prefab assets alone would have left every scene instance broken. The pipeline that fixed them is docs/samples-handoff.md, and the three scripts are in Tools~/SamplesBuilder/ so the sample can be rebuilt when the source scenes change.

closed  Published. The repo is crawfis/EventDrivenUGS, and the packages are consumed from it by git URL. Current release: 0.2.0.

partly open  Some of it has now run against live services. Boot, initialization and authentication have been exercised in a linked project: the sign-in modal renders and signs a player in, and the achievements catalogue load reaches Remote Config. That first play session immediately earned its keep — it found three defects a build could never have shown, all of them silent:

  • the catalogue was fetched before sign-in, so Remote Config returned an empty response and the failure was reported as a missing achievements key — blaming a deployment that was fine;
  • the sign-in modal had never rendered, because PlayerAccountLogin.uxml was malformed XML (an illegal -- inside a comment) and Unity imports such a file to an empty VisualTreeAsset with no error at import or at run time;
  • the leaderboard panel shipped a tier id for a board with no tiers.

A later session closed most of the rest. Leaderboard submission returns a real entry; Cloud Save achievements unlock and write; and the currency path banked a run’s coins into an Economy COIN balance, confirmed against the dashboard to the coin. Two findings came out of it, and neither was a defect in this package:

  • PlayerCurrencyController had never been placed in a scene in the consuming project. The code was correct and complete; the sole subscriber to CurrencySyncRequested simply did not exist, so every hop up to that signal fired and nothing wrote. A compile cannot show that, and neither can a survey of the package on its own — only a play session can.
  • the project defined no COIN currency in the environment it signs in to, which the package reported as “the currency id does not exist in this project’s Economy configuration” rather than as a silent zero. That diagnostic did its job: it named the cause exactly, and it is deliberately distinguished from an access denial.

Still unexercised: the two Cloud Code trusted backends, which need a deployed module.

closed  The cutover is done. RunnerUGSTemplate now consumes all three packages by git URL; Assets/UGS/Scripts and Assets/_Common are gone from it, and the game's half of the contract lives in Assets/UGSGlue/. Rolling back now means pinning an older commit, not declining to start.

Install shape

Four git URLs. UPM does not resolve git dependencies declared inside a package, so the siblings cannot be pulled in automatically — all four must be listed.

"com.crawfissoftware.eventspublisher": "https://github.com/crawfis/EventsPublisher.git",
"com.crawfissoftware.contracts": "https://github.com/crawfis/EventDrivenUGS.git?path=/Packages/com.crawfissoftware.contracts",
"com.crawfissoftware.common":    "...?path=/Packages/com.crawfissoftware.common",
"com.crawfissoftware.ugs":       "...?path=/Packages/com.crawfissoftware.ugs"

Registry dependencies — Core, Authentication, Cloud Save, Cloud Code, Leaderboards, Remote Config, Newtonsoft — are declared in package.json and resolve on their own.

How this was arrived at

Two adversarial survey passes, 48 agents, ~7.1M tokens. The first mapped the extraction across 8 dimensions; the second measured the exact Blocks API surface and designed each replacement. Every finding was re-derived by a second agent through an independent lens before being acted on — which is how the GeneratedBindings blocker surfaced in seven dimensions at once, and how the estimate that deleting the dead scripts would “drop 2 of 13 references” was caught naming a reference the asmdef never had.
