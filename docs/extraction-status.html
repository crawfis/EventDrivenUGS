Extracting Assets/UGS into a UPM package

Status of crawfis/CrawfisSoftware.UnityPackages — three packages, four commits, not yet pushed.

The two blockers, and why they were one

The extraction as originally scoped could not ship. Two independent findings turned out to have a single root cause.

1 — Licence. The 81 vendored files under ThirdParty/Blocks/ are Unity Asset Store Extension Asset content. The Asset Store EULA FAQ addresses this exact shape directly:

“A product is not ‘incorporated’ into the Licensed Product if it is designed to allow your end users to extract or download assets separately from the Licensed Product.”

A UPM package is precisely a thing consumers download and whose assets get extracted into their project. Runtime/ versus Samples~/ makes no difference, and neither does a private repo. The tree’s own THIRD-PARTY-NOTICES.md had flagged that this check would come due.

2 — GeneratedBindings. Found independently by 7 of 8 survey dimensions. CrawfisSoftware.UGS.asmdef referenced Unity.Services.CloudCode.GeneratedBindings, whose asmdef lives at Assets/CloudCode/GeneratedModuleBindings/ — in the consumer’s Assets/. A package assembly cannot reference that, so the package would not compile at all. Vendoring a copy fails too: the bindings folder and its asmdef name are hard-coded and regenerated on every “Generate All Modules Bindings”, producing a duplicate-assembly collision.

One cause. Of the 11 files needing GeneratedBindings, 6 were the dead scripts already slated for deletion and 5 were inside the Blocks tree. After the deletions, Blocks was its sole consumer — so removing Blocks from the package dissolved both blockers at once.

Defects fixed along the way

These were live bugs in the existing code, found by reading it closely enough to replace it.

WhereDefect
DebugEventFileLogger Unguarded [RuntimeInitializeOnLoadMethod] opened debug_event_log.txt with append:false next to the executable on every run of every project referencing the package — truncating a file at the project root each Play, and throwing UnauthorizedAccessException from Awake in a Program Files install. Now editor/dev-build only, persistentDataPath in players, open failures warned rather than propagated.
Both achievement hooks Yielded a Task from inside a coroutine. A coroutine yielding a non-YieldInstruction just resumes next frame, so every unlock was fire-and-forget with unobserved exceptions.
DistanceBasedAchievements Looked the achievement up and dereferenced the result; Find returns null until the catalogue is fetched, so the first unlock threw before it was attempted. Also subscribed an anonymous lambda with no unsubscribe — the repo’s one hard rule.
LeaderboardPlayerController data as float? then .Value. A null or non-float payload threw from inside the handler, killing the submission without publishing a failure.
Achievement icons A shared static list, last-writer-wins: whichever of the panel and the toast initialised second blanked the other’s icons. The notification prefab carried a hand-written guard for it. The icon library now merges by name; the guard is gone.
PlayerSignInController Registered a signed-in callback duplicating a subscription it already had — and which, unlike the subscription, could never be unregistered.

Contracts that fail silently

Three names are load-bearing beyond C#. Each breaks at runtime with no compile error, so each carries a comment at its declaration.

  • "hidden" — the USS class PlayerSignInController declares as its own literal. Renaming it in the stylesheet alone hides nothing.
  • Icon filenames — thumbnail, _blue, _green, _red, _black. Matched against Texture2D.name from definitions that live server-side in Remote Config, so a renamed asset breaks a deployed game.
  • <CrawfisSoftware.UGS.Authentication.PlayerSignIn/> — a UXML tag resolved by string at import. Rename the class or namespace and the modal renders empty.

What remains

yours  Scenes, prefabs and the leaderboard panel. Scene and prefab YAML is your work, not mine. The 8 scenes, both achievement prefabs and the UI assets still need to move into Samples~/UGS-Scenes/ and be rewired off the deleted Blocks GUIDs — the icon list on the achievements prefab, the sign-in panel settings, and the leaderboard prefab instance in Leaderboards.unity.

The leaderboard display (LeaderboardPanel → TabView → ListView → row) is specified in the design spec but not built, because it is prefab-shaped. LeaderboardQuery — the part that is code — is done, and score submission never used Blocks at all.

open  Compile verification. Nothing here has been through a Unity compile. The replacements are written against documented SDK shapes, but the Cloud Save and Leaderboards call sites in particular deserve a real build before you trust them. This is the single highest-value next step.

open  The .ach importer. Not addressed. It is Asset Store editor code that currently owns your achievement definitions. The recommendation from the survey is to drop it: definitions are read at runtime from Remote Config, so the authoring format is an editor-only concern and a ScriptableObject plus a small exporter would be strictly better in a package. AchievementsAccessControl.ac should not travel — it denies player writes to Cloud Save, which is exactly incompatible with the default backend.

open  The GitHub repo does not exist yet. Everything is local, in four commits. Nothing has been pushed.

safe  RunnerUGSTemplate is untouched and fully playable. Per the chosen sequencing, the cutover there is a separate later PR. Rolling back means simply not doing it.

Install shape

Four git URLs. UPM does not resolve git dependencies declared inside a package, so the siblings cannot be pulled in automatically — all four must be listed.

"com.crawfissoftware.eventspublisher": "https://github.com/crawfis/EventsPublisher.git",
"com.crawfissoftware.contracts": "https://github.com/crawfis/CrawfisSoftware.UnityPackages.git?path=/Packages/com.crawfissoftware.contracts",
"com.crawfissoftware.common":    "...?path=/Packages/com.crawfissoftware.common",
"com.crawfissoftware.ugs":       "...?path=/Packages/com.crawfissoftware.ugs"

Registry dependencies — Core, Authentication, Cloud Save, Cloud Code, Leaderboards, Remote Config, Newtonsoft — are declared in package.json and resolve on their own.

How this was arrived at

Two adversarial survey passes, 48 agents, ~7.1M tokens. The first mapped the extraction across 8 dimensions; the second measured the exact Blocks API surface and designed each replacement. Every finding was re-derived by a second agent through an independent lens before being acted on — which is how the GeneratedBindings blocker surfaced in seven dimensions at once, and how the estimate that deleting the dead scripts would “drop 2 of 13 references” was caught naming a reference the asmdef never had.
